# 开发与验证

项目使用 Manifest V3 和原生 JavaScript，没有构建产物。修改源码后，在 Chrome 扩展管理页面刷新扩展，并刷新播放页。

## 模块职责

- `lib/core.js`：设置与数据校验、语言代码、分词、UTF-8 分块、CSV 导出、LRU 缓存和最新任务队列。
- `lib/translation.js`：Chrome 本地模型生命周期、连续字幕语言识别、翻译调度和在线备用调用。
- `lib/mymemory.js` 与 `background.js`：受限在线请求、额度记录、域名权限和串行生词写入。
- `content`：原生字幕 DOM 适配、Shadow DOM 显示和查词播放控制；`native.css` 仅作用于已接管的原生字幕标记。
- `popup` 与 `vocabulary` 页面：设置及本地生词管理。

内容脚本只在 `https://www.netflix.com/*` 注入。字幕源为 `.player-timedtext-text-container` 或对应 `data-uia` 元素；不读取其他扩展字幕、不拦截视频网络请求，也不依赖 Netflix 私有播放器 API。

接管后使用 `data-netflix-translate-hidden` 标记配合独立样式隐藏原生字幕，不修改 Netflix 的行内样式。Netflix 重写布局样式时仍然保持隐藏；关闭、异常或字幕消失时撤销标记，保留 Netflix 当时的样式。

本地翻译运行在内容脚本的窗口上下文；Service Worker 只承担在线翻译和数据操作。手动准备按钮直接调用 `Translator.create()`，保留用户激活。已缓存语言包在浏览器允许时自动恢复；模型下载、请求超时及会话失效均有独立处理。

```mermaid
flowchart LR
    A[Netflix 原生文字字幕] --> B[会话与句子快照]
    B --> C[连续样本识别语言]
    C --> D[最新任务队列与缓存]
    D --> E[Chrome 本地翻译]

```

## 命令

需要 Node 18 或以上，无需安装 npm 依赖。

```sh
npm run check
npm test
npm run test:browser
```

- `check` 验证 Manifest 引用、注入站点范围和脚本语法。
- `test` 运行真实核心模块的定向测试，网络请求和 Chrome 存储在内存中模拟。
- `test:browser` 只监听 `127.0.0.1:8765`。打开 `http://127.0.0.1:8765/watch/999`，点击「运行浏览器测试」。可通过 `NT_TEST_PORT` 指定其他端口。
- 真实本地翻译能力测试页：`http://127.0.0.1:8765/tests/local-engine.html`。它调用真实 Chrome API，首次点击会下载语言包。
- 模拟设置与生词本：`http://127.0.0.1:8765/popup.html?fixture=1`、`http://127.0.0.1:8765/vocabulary.html?fixture=1`。模拟数据与扩展本地存储完全分开。

## 验收边界

自动化测试覆盖最新字幕调度、过期结果丢弃、UTF-8 分块、额度与权限、下载失败、查词暂停和恢复、日韩文分词、收藏去重及 CSV 转义。模拟页面的视频状态和翻译响应是测试替身，只验证适配与界面逻辑。

真实 Netflix 需单独验证当前页面 DOM、实际语言包、影片字幕轨道、播放控制、全屏及换集。测试时单独启用本扩展，不能把其他扩展显示的双语字幕作为本项目成果。

离开影片、关闭插件、跳转时间、切换字幕轨道或更换播放器后，旧会话结果不得再渲染；查词收藏必须使用打开时的字幕上下文。源码或上述接口变化后，应优先复测这些边界。
